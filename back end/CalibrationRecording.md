# Calibration recording and offline recovery

Each automatic calibration creates a separate directory under captures/YYYY-MM-DD/selfcal/runs. Starting another run does not overwrite previous runs.

- Manifest.json records the starting motor state, arm geometry, home reference, joint limits, workspace coordinates, previous camera calibration, Python/package versions, and source hashes. The sources directory contains copies of the relevant backend and frontend code.
- observations contains the original encoded camera frames, including misses and unstable captures. Each file includes the corresponding display-frame joints, marker/mirroring convention, planned pose, per-frame timestamps and video counters, per-frame servo readings and joint positions, camera settings, capture-start/end servo readings, receiver-side bridge state, and the tracker state before detection.
- records contains marker checks, motion requests/results, the complete pose plan, detection outcomes, full fit reports (each with its camera model and quality problems), and run completion or cancellation. An interrupted run retains everything written before interruption even if it has no Finish record.
- Every fit that computes a camera is saved and applied (quality problems are warnings; only the user rejects a calibration). Saving first writes CalibrationReplaced: the whole camera_calibration.json it replaces. The new file names that record under "replaced". The user's Reject calibration (/selfcal/reject) writes UserRejected (the whole rejected file, reason and time) beside it and restores the replaced file, with last_rejected saying what was rejected. CameraSaved records the saved model, its quality problems and the CalibrationReplaced record. A save without a run on disk records these under captures/YYYY-MM-DD/calibration_changes.
- Session.json keeps the accepted observations for that particular run, plus red_poses: every pose's measured gripper frame and all of its stable red blobs, whether or not the live tracker found the tape. Solving picks the tape among those blobs by camera consistency. The top-level selfcal_session.json is only a latest-session convenience copy.

Original capture payloads are flushed to disk before detection. A recording failure aborts the calibration instead of silently discarding data. The app checks the recorder version before resetting a session or requesting calibration motion.

ReplayCalibration.py reprocesses a run without importing motor control or applying a camera model. Its positional argument is the run directory. The optional --hints argument names a JSON file mapping pose indices to native, unmirrored image pixel coordinates with u and v fields. An observation filename can be used instead of a pose index when a run contains repeated poses. Hints allow selection of the actual tape in archived frames after a detector mistake.

Replays create another run directory beside the original, recording the source run and supplied hints. A replay re-detects every red blob from the saved frames, so an older run whose tracker followed the wrong blob is re-solved with the current tape assignment; hints are rarely needed. Replaying the 2026-09-13 22:31 run this way turns its rejected 110 px fit into an accepted one (27 poses, 0.55 cm at the tape). They preserve the original archive and current camera calibration. The replay's FitReport.json contains the candidate model and validation results (problems: the quality warnings). Applying a replayed model remains a separate action. Captures marked unstable remain archived for investigation and are excluded from automatic replay.

Tests: TestCalibrationArchive.py exercises independent runs, configuration/source snapshots, rejected and incomplete captures, disk failures, plan/fit/completion recording, and a synthetic 36-pose run recovered entirely from saved images and joint data. TestRedTape.py covers marker selection and detection. TestCalibrationNeverRejected.py saves a run for each former rejection reason with its warning, rejects and restores through the archive, and keeps the calibration when nothing could be computed. TestCalibrationUi.mjs checks browser-side per-frame recording and refusal to use an older recorder.
